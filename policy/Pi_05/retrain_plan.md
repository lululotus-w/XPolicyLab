# Pi0.5 classify_objects 微调:失败复盘、重训方案与对照实验设计

> 日期:2026-09-23(**2026-10-09 修订**:根因诊断更新,见 §2.4/§2.5;重训 v2 进展见 §7)
> 任务:classify_objects(三分类物体入篮)| 机器人:arx_x5 双臂(关节控制,14 维)| 策略:Pi0.5(VLA)

---

## 1. 背景与目标

- **基础权重**:`RoboDojo-sim-arx_x5-joint-0`(仿真预训练 checkpoint,step 59999),在 classify_objects 测试集上成功率 **10%**。
- **目标**:用回流采集的 98 条成功轨迹做微调(flywheel 数据飞轮),提升 classify_objects 成功率。
- **第一次微调(9/16–9/18)已失败**:成功率不升反降。本文档记录失败分析、修正后的重训方案(方案 A)、以及用于归因的对照实验设计。

## 2. 第一次训练复盘(失败)

### 2.1 训练配置

| 项 | 配置 |
|---|---|
| 步数 | 60,000(≈24 epoch,98 条数据) |
| batch | 32(4×L20,FSDP 分片) |
| 学习率 | cosine 峰值 2.5e-5 → 2.5e-6,warmup 1000 |
| 优化器 | AdamW(β1=0.9, β2=0.95, wd=1e-10, clip 1.0),EMA 0.99 |
| 训练范围 | **全参数**(视觉塔、LLM、动作专家全部更新) |
| 结果 | loss 0.474 → 0.0007,训练"完美收敛" |

### 2.2 评测结果(统一协议:同任务、50 episodes、同一批场景布局)

| 模型 | 评测场景 | 成功率 | 均分 |
|---|---|---|---|
| 基础权重 joint-0(微调前) | seed0 测试集 | **10%** | 22.7 |
| 其他 sim checkpoint(8月) | seed0 测试集 | 6~26% | 15~40 |
| 微调版 step 10000 | seed0 测试集 | 4% | 10.8 |
| 微调版 step 59999 | seed0 测试集 | 2% | 12.0 |
| 微调版 step 59999 | seed1 训练分布场景 | **0%** | 16.0 |

**结论:微调后比微调前差 5–10 倍,连训练分布场景上都全军覆没。**

### 2.3 数据质量排查(已排除数据原因)

| 检查项 | 方法 | 结论 |
|---|---|---|
| 成功筛选机制 | 读采集代码(`eval_env.py`):仅 `success[0]=True` 时保存 | 98 条全部为判定成功的 episode |
| 成功判定可靠性 | 读任务代码:`classify_objects.run_reward()` 要求①全部物体进对应篮子②物体落定③机器人归位,三条件同时满足 | 严格多条件判定,非单帧误判(区别于 build_tower 的已知 bug),伪成功风险低 |
| 画面抽检 | 从 parquet 抽 3 条 episode 首/中/尾帧人工查看 | 3/3 真实成功:抓取、搬运、入篮全程正常,图像清晰,layout 有多样性 |
| 数值体检 | 全量 80,909 帧检查 | 无 NaN、无冻结维、夹爪全范围使用、帧间跳变正常(仅 5/80811 帧毛刺,可忽略) |

**数据合格 → 失败根因锁定在训练方式本身。**

### 2.4 根因诊断(2026-09-24 修订:归一化系数错配为主因)

**主因(已实锤):norm_stats 与基础权重不配套。**

两次微调(60k 全参数版和方案 A)的配置都把 assets 指向了 `gs://openpi-assets/checkpoints/pi05_base/assets` + `asset_id="arx"`(从真机 ARX 公开数据模板抄来的),而基础权重 joint-0 是在 `arx_x5_sim` 统计(sim 预训练数据集算的)的归一化空间里训练的。权重和统计是两条独立链路,openpi 不会校验配套性,错误全程静默。

数值证据(98 条轨迹 vs 两套统计,逐维越界比例):

| 维度 | `arx_x5_sim`(正确) | `arx`(实际误用) |
|---|---|---|
| 大关节(q99≈2.5 rad:dim 1/2/8/9) | 越界 4~11% | **越界 48~51%(归一化后 ≈3.8,远超 [-1,1])** |
| 其余关节 | 0~2% | 11~16% |
| 平均 | 7.3%(边界效应) | **24.9%** |

后果:喂给 joint-0 权重的 state 约一半维度严重超出它训练时见过的输入空间,行为必然崩溃——**与训练超参、冻结策略无关**。训练 loss 照样能降(模型可以拟合任何归一化空间),评测机制上照样能跑(训练/评测用同一份错误统计,"错得一致"),唯一的暴露途径就是成功率本身。

**次要因素(被污染,无法单独归因):灾难性遗忘。**

原诊断(§下文保留)认为 60k 步 × 全参数 × lr 2.5e-5 导致"背熟 98 条数据 + 冲毁通用能力"。该假设与当时的 loss 曲线和评测形态吻合,但 60k 版的失败同时叠加了归一化错误,**两者贡献无法分离**。原始证据链(供参考):
1. loss 降到 0.0007 = 把 98 条轨迹"背熟"(memorization);
2. 均分从 22.7 跌到 ~11;
3. seed1(训练分布场景)0%;
4. 基础权重 10% vs 微调后 0–4%。

关键认知(仍然成立):**这批新数据唯一的新信息在"任务行为"层**;感知层和具身层没有新信息,让数据改写这两层是纯风险、零收益。

### 2.5 为什么当时没发现

1. **无报错**:loss 正常收敛、评测正常出数,一切"机械上正确";
2. **先入为主**:0-4% 的结果与"灾难性遗忘"的常见叙事吻合,首个似是而非的解释即被接受;
3. **流程缺口**:最初设计里没有验证集,评测又直接在 seed0 上做,结果差时缺少"换个已验证正确的配置对照"的反思抓手;
4. 转折点是 09-24 方案 A ckpt2000 的反常结果:参数几乎没动、视觉塔冻结,理论上应≈基础权重(10%),却评出 0%(均分 7.3,比失败版还低)——排除了训练本身,才倒查到评测/训练的输入空间不一致。

## 3. 重训方案 A(当前方案)

### 3.1 配置对比

| 项 | 第一次(失败) | 方案 A(实际执行) | 理由 |
|---|---|---|---|
| 总步数 | 60,000(24 epoch) | **6,000(≈1.2 epoch)** | 只看数据一遍多,没有"背熟"的机会 |
| 峰值学习率 | 2.5e-5 | **2.5e-6** | 与步数合并,总更新预算缩小 ~200 倍 |
| warmup | 1000 | 100 | 与总步数等比 |
| norm_stats | pi05_base 的 `arx`(错) | **joint-0 自带的 `arx_x5_sim`** | 归一化空间必须与基础权重一致(§2.4 主因) |
| 视觉塔(SigLIP) | 全参数更新 | **冻结** | 新数据对感知层零新信息;冻结 = 切断遗忘的主通道 |
| LLM + 动作专家 | 全参数 | 全参数(保持) | 新信息全在行为层,保留全秩学习容量 |
| checkpoint | 每 1000 步,留里程碑 | **每 500 步全保留** | 训后逐个评测选优,自带"更新预算剂量曲线" |
| 验证集 | 无 | **seed1/seed2 场景 = 验证集;seed0 = 测试集(终评才碰)** | 补上缺失的模型选择环节,防测试集污染 |

### 3.2 两个改动的设计逻辑

**改动一:更新预算 ↓200 倍(步数 × 学习率合并为一个因子)**
步数和学习率不是独立变量 —— 它们共同决定参数被推动的总距离(60000×2.5e-5=1.5 vs 3000×2.5e-6=0.0075)。针对的根因:更新量远超 98 条数据的信息量。

**改动二:冻结视觉塔**
针对的根因:感知层被无新信息的数据冲刷。冻结 SigLIP(路径过滤 `.*PaliGemma/img.*`)是"按模块划界" —— 焊死最通用、最不该动的部分,把全部学习容量留给唯一有新信息的行为层。

### 3.3 为什么不是 LoRA(以及为什么不是"冻结+LoRA")

1. **openpi 的 LoRA 默认不保护视觉塔**(已读代码确认:`get_freeze_filter()` 的 AND 语义下,`img` 路径不匹配 `.*llm.*` → 视觉塔照常全参数训练)。用内置 LoRA 恰恰没护住最需要护的部分。
2. **容量错配**:LoRA 把行为层更新也压进 rank-16 瓶颈。我们的问题是"学太狠",不是"容量不够";在数据只有 98 条时,低秩瓶颈反而增加欠拟合(学不会行为映射)的风险。
3. **工程风险**:LoRA 需要换模型变体、验证 sim checkpoint 加载兼容性、deploy 联动改造,失败点多;冻结只需 config 加一个 filter,checkpoint/部署格式零改动。
4. **升级路径保留**:方案 A 失败时,LoRA(+冻结)是现成的下一档(见 §4)。

### 3.4 资源

- 显存:全参数训练态 ~53.6G(参数+m+v+EMA)→ 冻结视觉后 ~50.4G。
- 4 卡(46G L20):宽裕;**2 卡:可行**(~25G/卡 + 激活),是当前 GPU 4-7 被占用情况下的现实选项。
- 时长:~3,000 步 × 2.6s ≈ **2.2 小时**(对比第一次的 42 小时)。

## 4. 对照实验设计(用于归因)

### 4.1 问题

方案 A 同时改了"更新预算"和"冻结范围"两个因子 —— 单跑 A,成功后无法归因是哪个改动起了作用。完整的 2×2 消融:

| | 不冻视觉塔 | 冻视觉塔 |
|---|---|---|
| **高预算**(60000×2.5e-5) | ✅ **已有**:第一次训练(失败,0–4%) | 不计划跑(42h,性价比低) |
| **低预算**(3000×2.5e-6) | **对照实验(待跑,2.2h)** | 方案 A(待跑,2.2h) |

**完整归因只需补一个对照运行。**

### 4.2 归因解读表

| 方案 A 结果 | 对照(不冻,低预算)结果 | 归因结论 | 对后续的指导 |
|---|---|---|---|
| 成功 | 成功 | 功劳主要在"削预算",冻结是多余保险 | 扩数据后可撤掉冻结,简化训练 |
| 成功 | 失败 | 冻结是必要的 | 后续训练(包括加数据)保留冻结 |
| 失败 | — | 低预算+冻结都不够 | 升级 LoRA 档(冻结视觉+rank-16 适配器) |

### 4.3 方案 A 内部自带的剂量曲线

A 每 500 步存档(500/1000/.../3000),冻结恒定、预算递增。逐个 ckpt 评测即得到"成功率 vs 更新预算"敏感曲线:若成功率先升后降,曲线峰值同时回答"3000 步是否仍然过多",并给出过拟合起点。

### 4.4 执行顺序与理由

1. **先跑方案 A** —— 主目标优先(拿到能用的策略),且冻结版显存适配当前可用的 2 张共享卡;不冻结的对照需要 4 卡空闲(53.6G 双卡放不下)。
2. A 跑完 → 逐 ckpt 在 seed1 场景评测(每个 ~20 episodes 快筛)→ 选优 → seed0 终评(50 episodes)。
3. GPU 空出 4 卡后 → 跑对照(2.2h)→ 完成归因。
4. 归因结论写入下一轮(回流更多数据)的训练决策。

### 4.5 评测协议(防测试集污染)

- **验证集**:seed1 + seed2 场景布局(`ROBODOJO_SCENE_SEED=1/2`,各 110 个 layout)—— 与训练数据同分布,用于 checkpoint 选择与对照实验;
- **测试集**:seed0(默认,110 个 layout)—— 只在最终报告时跑;
- 注意:同 checkpoint 在验证/测试集上的小差距(±1–2 个成功/50 eps)属统计噪声,不做过度解读。

## 7. 重训 v2 进展(2026-10-09 更新)

### 7.1 训练

- **时间**:09-24 22:53 → 09-25 02:53,exit 0,零异常(wandb offline 模式,规避代理 SSL 问题);
- **配置**:`pi05_classify_ckpt0_conservative_freeze_vision`,6000 步 @2.5e-6,bs16,2×L20 FSDP,冻结视觉塔,**assets 改为 joint-0 的 `arx_x5_sim`**;
- **产物**:12 个 checkpoint(500…5500、5999)全部完整,assets 均带 `arx_x5_sim/norm_stats.json`;
- loss:0.39 → 0.0048,前 500 步完成大部分下降,2000 步后进入缓降平台。

### 7.2 评测(剂量曲线,已完成)

统一协议:seed0、50 eps(与基础权重 8/5 基线同口径):

| checkpoint | seed0 成功率 | 均分 | 备注 |
|---|---|---|---|
| 基础权重 joint-0 | 10% | 22.7 | 8/5 基线 |
| 基础权重 joint-0 @ seed1 | — | — | **6%**(训练分布参照) |
| 坏管线 ckpt2000(错误统计) | 0% | 7.3 | 9/24,已被修复方案取代 |
| v2 ckpt2000 | 4% | 14.2 | 10/9 |
| v2 ckpt4000 | 4% | 12.3 | 10/10 |
| v2 ckpt5999 | 4% | 13.6 | 10/10 |
| **v2 ckpt5999 @ seed1(训练分布)** | **6%** | 16.4 | 10/12,50 eps |

**剂量曲线全程平线(4%→4%→4%);seed1 上与基础权重打平(6% vs 6%)。**

### 7.3 结论:98 条数据 = 行为零增益,瓶颈在数据信息量

证据链:
1. **行为保持但零增益**:seed1(训练分布)上微调版与基础权重完全打平(6% vs 6%);seed0 上 2/50 vs 5/50 的差值在统计噪声内(P(≤2|p=0.1)≈11%,不显著)——微调在行为层面≈一次空转;
2. loss 0.0048 = 训练数据被拟合得很好,但点态速度场拟合没有转化为任何闭环行为增益;loss 平台(2000 步后)+ 剂量曲线平线说明继续训练不改变结局;
3. 失败视频:动作平滑、会抓会放(电机能力完好),但分类未完成/夹爪未开;
4. 数据覆盖薄:98 条 episode 分布在 52 种类别三元组上,平均每种组合仅 ~2 条。

**判定:方案 A 配方(冻结视觉+低预算+正确 norm_stats)实现了"行为无损",但 98 条数据的信息量不足以产生行为增益。提升成功率的前提是数据飞轮回流更大规模、覆盖更全的演示数据。**

### 7.4 后续决策

- **主攻数据**:数据飞轮下一轮回流,目标数百条量级、覆盖全部类别组合与更多 layout;训练配方沿用方案 A(冻结视觉 + 剂量曲线 + 正确 norm_stats),步数随数据量等比放大;
- **不再做**:在 98 条数据上调超参(提 lr / 换 LoRA 都只是改变"背"的方式,不改变数据不足的事实);
- 对照实验(低预算+不冻结,需 4 卡)——其解读已随 §2.4 修订:只回答"冻结 vs 不冻"在低预算下的差异,不再能验证"灾难性遗忘"假设。

## 附录 B:本次排查中修复的基础设施问题

1. **norm_stats 错配(主因,见 §2.4)**:训练配置的 assets 指向 `pi05_base` 的 `arx` 统计而非 joint-0 的 `arx_x5_sim`。修复:config.py 的 AssetsConfig 改为 joint-0 checkpoint 自带 assets + deploy.yml `repo_id: arx_x5_sim`。教训:启动训练必查日志首行 `Loaded norm stats from ...` 是否指向基础权重自己的 assets;
2. RoboDojo 主环境与 openpi venv 均缺 `msgpack-numpy`(评测 ws 协议依赖),已分别安装;
3. 评测断点续评机制:`_resume_*.json` 为中断进度存档,评测正常完成后自动删除,不影响结果;
4. wandb online 模式在本机代理下会 SSL 失败并拖死训练进程(09-24 16:08 那次启动即因此夭折):训练统一加 `WANDB_MODE=offline`。
